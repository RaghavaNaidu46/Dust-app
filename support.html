Support

Questions, bug reports and feature requests all go to one place.

Open an issue on GitHub — it is read by a person, and you do not need an account to read what is already there.

Found something Dust offered to delete that it should not have? Please report it with the path. Dust is built so that cannot happen, and a case where it did is the most important bug it can have.

Common questions

Why does Dust need Full Disk Access?

App caches live inside folders macOS protects — containers, and parts of ~/Library. Without the permission Dust can still scan, but the totals come out low. It will say so plainly rather than quietly under-reporting.

Dust reads only metadata: how large a file is and when it was last touched. It does not open files or read their contents.

How do I grant it?

System Settings → Privacy & Security → Full Disk Access, then switch on Dust. The welcome screen has a button that takes you straight there, and it notices when the permission lands. You can reopen that screen any time from Settings → General.

Is it safe to click “Free up all safe”?

That button only touches items Dust classes as both disposable and actionable. Your documents, Desktop, Pictures, Movies, Music, iCloud Drive, Keychains, Mail, Messages and iOS device backups are excluded during discovery, so they never become candidates at all.

Anything reversible is moved to the Trash. Leftovers from uninstalled apps, old downloads and working simulators are never included — those come through a review sheet where every box starts unticked.

What exactly gets deleted?

Expand any row in the panel to see the individual folders, their sizes and when each was last used. Right-click a row and choose Choose items… to pick them one at a time instead of freeing the whole group.

Dust says some space “reclaims after restart”. Why can’t it free that now?

Deregistered simulator runtimes can leave multi-gigabyte files under System Integrity Protection. Deleting them fails even for an administrator; macOS releases them itself on the next restart. Dust shows them separately and will not ask you for a password that cannot help.

Why is some space listed as “needs an administrator”?

Parts of /Library are owned by the system. Dust shows their size for information and leaves them alone rather than escalating privileges to delete system files.

Does Dust scan in the background or slow my Mac down?

No. There is no background scanning, no timer and no filesystem watcher. A scan runs when you open the panel and is cancelled when you close it. An optional periodic rescan exists in Settings, is off by default, and is skipped on battery, in Low Power Mode and when the Mac is running hot.

Does it send anything anywhere?

No. Dust makes no network requests at all — no analytics, no crash reporting, no update check, no account. See the privacy policy.

Will it scan my source code folders?

Only the ones you add. Settings → Scanning takes project roots, and nothing inside a source tree is walked until you add one. Matching is by exact directory name (node_modules, build, Pods, .build); names that are checked in by some projects, like dist or vendor, are opt-in on top of that.

How do I protect a folder from Dust entirely?

Settings → Protected. Anything listed there is excluded while Dust is still building its list, so it never appears as a candidate in the first place.

How do I uninstall it?

Quit Dust from the menubar, move the app to the Trash, and delete ~/Library/Application Support/Dust. That folder holds only the cached scan result and your settings.

Requirements

macOS 14 Sonoma or later. Apple silicon and Intel.
